`src/commands/new/write-plan.ts` currently has a private helper that does `getTypeDefByPath(schema, typePath)?.outputDir`, then errors when it is absent. In contrast, public `getOutputDir(schema, typeName)` in `src/lib/schema.ts` resolves in order: the type's explicit directory, an ancestor's explicit directory, or `computeDefaultOutputDir` from pluralized hierarchy names. Owned creation already bypasses pooled resolution and returns `ensureOwnedOutputDir(...)`.

`src/commands/new/interactive.ts` constructs frontmatter with `type`, schema/template values, and system ID later in the write plan. It prompts for `Name` when no filename pattern exists and returns the prompt as `itemName`, but does not assign it to `frontmatter.name`. When a filename pattern fully resolves, it never asks for a name; the pattern result becomes `itemName`. When a filename pattern cannot resolve, it prompts for a fallback name and again only uses it as `itemName`.

`src/commands/new/json-mode.ts` accepts built-in `name`, validates the merged frontmatter, applies defaults, and resolves a filename. With a fully resolved filename pattern, the pattern result is used as `itemName` while input `frontmatter.name` remains the persisted identity. Without a pattern, or when a pattern cannot resolve, `frontmatter.name` is required and becomes `itemName`.

`src/commands/new/paths.ts` always sanitizes `itemName` to create the physical filename and reports any transformation; it does not mutate frontmatter. Thus a JSON name `Foo/Bar` is persisted as `name: Foo/Bar` while the file becomes `FooBar.md`.

The interactive PTY suite's simple flow currently asserts type/status/priority but not persisted name. JSON tests already assert that `Foo/Bar` stays in frontmatter while the path is sanitized. Templates, child instance scaffolding, owned notes, and forks have dedicated tests.
