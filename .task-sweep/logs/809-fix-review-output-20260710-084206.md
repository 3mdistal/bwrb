## Blockers

1. **Regression test does not reliably prove the fix** (`tests/ts/commands/config.test.ts`, "round-trip configured $TODAY defaults"). The test depends on the wall-clock date:
   - On days **13–31**, `$TODAY` under `DD/MM/YYYY` produces an *unambiguous* slash date (e.g. `25/07/2026`) that the pre-existing format-agnostic parser already normalized to ISO — so the test **passes on unfixed code** roughly two-thirds of the month. It only exercises the original failure (ambiguous day ≤ 12) on days 1–12.
   - The assertion `expect(content).toMatch(/today: \d{4}-\d{2}-\d{2}/)` checks shape only, not correctness. A month/day-swapped normalization (e.g. `05/07` → `2026-05-07` instead of `2026-07-05`) would pass. Compute today's expected ISO string (with a midnight-tolerant comparison, or a mocked clock) and assert the exact value. As written, this does not truly prove "config edit → new `$TODAY` → audit" per the fix's stated purpose.

## Non-blocking notes

2. **Silent fallback contradicts the configured order** (`src/lib/validation.ts`, `normalizeToIsoDate`). If the value fails the configured pattern (e.g. `25/12/2026` under `MM/DD/YYYY` — month 25 fails calendar validation), it falls through to the format-agnostic parser and is accepted as EU-order December 25. So a vault explicitly configured US-order still silently accepts EU-order input. Largely pre-existing behavior, but the new docs ("A value that exactly matches the configured format can be parsed without guessing", `docs/skill/SKILL.md`) don't mention this fallback, which is mild documentation drift. Consider either documenting or rejecting non-matching slash dates once a format is configured.

3. **Parameter inserted mid-signature** (`src/lib/validation.ts`): `dateFormat` was added before optional `calendarContext` in both `validateDateValue` and `validateFieldType`. Any call site outside this diff passing `calendarContext` positionally would now misalign. TypeScript should catch this at compile time (string vs. object), but appending the new parameter last would have been lower-risk.
